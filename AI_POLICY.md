# AI policy

This project was largely written with Claude Code under one maintainer's direction and review (see "How it was built" in the [README](README.md)). The same standard applies to contributions: use AI tools if they help you. This policy is about what you post, not which tools you use to write it.

- **A person reads it and sends it.** Don't wire a bot or an agent up to open issues, comment or submit pull requests for you.
- **Write issues and discussion posts yourself.** Fill in the template in your own words and answer maintainers yourself.
- **Say what you observed, not what an assistant guessed.** An AI's theory about the cause is not a diagnosis. If you include one, label it as a guess.
- **Read your code before you submit it.** Say in the pull request that AI was used, and be ready to explain every line.
- **If we misjudge something you wrote, say so.** We'll take you at your word.

## Why

This is a security-adjacent project with one maintainer. Every pull request has to be read, and a change to PIN handling, secrets, rate limiting or the duress path is only safe if the author understood it. Unreviewed generated code costs the reviewer more time than it saves the author, and a confident wrong diagnosis sends everyone down the wrong path.

## What happens

Issues and pull requests that look like unreviewed AI output may be closed without a detailed review. It is not a judgment of you: resubmit it after you have read it, tested it and written it up yourself.

This applies to issues, discussions, pull requests, reviews and commit comments.
